# v0.17 — Live-ops hardening

> **Depends on:** v0.16 · **GDD sources:** §12.3, §21.4, §22.3, §24 (all), §26 (all), §27 (all), §29.1 crash row, §34.1 Q6 crash policy, Q157

## Objective

Make the game safe to run at scale:
- server-side telemetry for the economy and balance;
- a security pass over every remote against the GDD threat model;
- performance work for full 30-player servers on mobile;
- the crash-recovery mechanism that returns items after a whole-server crash where possible.

## Player-facing result

Mostly invisible:
- Fewer exploiters.
- Smoother full servers.
- After a server crash mid-fight, players see "Server crashed — your items were recovered" on their next visit when recovery succeeded.

## Confirmed rules

- **A server crash mid-fight should return items if possible** (Q157). A crash is **not** a normal logout and must not create a fake body in a server that no longer exists (§29.1, §34.1).
- **Any ordinary logout during active play still loses items** (Q157). Crash recovery must not become a way around that.
- **Recovery never duplicates**: items already looted, traded or dropped and claimed by others are not restored (§34.1 crash policy).
- **Every abuse case in GDD §24** has an automated security test before release (§24).
- **Telemetry** records server-side structured events for runs, harvests, crafts, drops, pickups, events, bosses, portal events, vault receipts, Forge operations, Permanent ownership, raids and sinks (§26.3).

## Systems and modules

| Path | Responsibility |
| --- | --- |
| `src/server/Services/RunCheckpointService.luau` | Periodic, compact snapshots of each active player's run inventory to MemoryStore (with expiry), keyed by run ID and server JobId |
| `src/server/Services/CrashRecoveryService.luau` | On the next lobby join: detects an unfinished run whose server is gone (no heartbeat, no corpse, no departure record), validates the snapshot, restores once through the operation journal |
| `src/server/Services/AnalyticsService.luau` | Structured events and Roblox Analytics custom events; currency faucets and sinks; anonymous segmentation (§26.3) |
| `src/server/Services/AntiExploitService.luau` | Shared rate limits, movement sanity checks, remote schema validation, violation logging and escalation |
| `src/server/Infrastructure/RemoteGuard.luau` | Typed argument validation for every RemoteEvent and RemoteFunction |

**How crash recovery tells a crash from a logout:**
- Ordinary departure writes a departure record and a corpse first.
- A server that shuts down on purpose runs `BindToClose`, which saves.
- A crash leaves an unfinished run with a stale server heartbeat and **no** departure record.

Only that last case is eligible. Items are restored minus anything the checkpoint log shows as transferred.

## Data and persistence

- `profile.receipts.crashRecovery[runId]`: status and restored items.
- MemoryStore checkpoints: short-lived and never the source of truth for the vault.
- Analytics events are bounded and anonymised. No personal information in logs (§23.3).

## Security and anti-exploit

Implement and test every GDD §24 row, including:
- forged Permanent IDs;
- double Forge requests;
- simultaneous devices;
- teleport mid-operation;
- death plus extraction races;
- center bonus replays;
- ineligible trades;
- trade interruption;
- double purchase receipts;
- rebirth replays;
- repeated 25% boss grants;
- negative quantities;
- DataStore budget exhaustion;
- structures overlapping portal auras.

Add movement and speed checks for sprint and crawl.

## UX and accessibility

- Recovery notice in the lobby and world menu.
- Clear error states for throttled saves (pending, never "saved").

## Validation

**Automated:**
- one security test per §24 row;
- crash-recovery specs: crash eligible, logout ineligible, shutdown ineligible, already-looted item excluded, restored once;
- remote schema fuzzing on malformed input.

**Live checks (§27.2):**
- Kill a test server process mid-fight: items recover once.
- Quit normally: no recovery.
- Poor mobile network and client-close mid-portal tests.
- Load tests with many dropped items, structures and effects.
- 30-player profiling on real devices.

**Balance review (§26):**
- Measure secured output per run, time to first Permanent, center portal risk-adjusted value, raid times and solo vs tribe viability.
- Compare with the §26.2 healthy and warning signals.

## Exit criteria

- [ ] Crash recovery restores items once and only after real crashes.
- [ ] Every §24 abuse case has a passing automated test.
- [ ] Telemetry dashboards for the economy and balance.
- [ ] Performance budget met on full mobile servers.

## Scope boundary

Platform outages that lose MemoryStore data cannot be recovered. This is documented, and support tools need audited restoration IDs (§24).
