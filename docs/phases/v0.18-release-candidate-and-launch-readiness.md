# v0.18 — Release candidate and launch readiness

> **Depends on:** v0.17 · **GDD sources:** §13.2, §27 (all), §28 step 9, §36.6, §38.4, §39.6, §41.3, §42.3, platform notes in §38.1

## Objective

Freeze features, run every acceptance and regression suite in the GDD against the published place, fix what fails, complete platform and store requirements, and promote the result to **v1.00**.

## Player-facing result

A launch-quality Flintborn: the complete loop, every confirmed system, polished onboarding and stable full servers.

## Confirmed rules

- **Feature freeze:** only fixes, balance and polish. Any new rule goes back through the GDD first.
- **All confirmed rules from GDD revisions 0.1–1.5** hold. The regression lists in §27.1, §31.7, §34.4, §35.4, §36.6, §37.4, §38.4, §39.6, §41.3 and §42.3 are the launch test plan.
- **Publishing only from `main`**, and the place version history kept for rollback (`docs/roblox-live-deployment.md`).
- **Monetization compliance:** every paid benefit has an earned equivalent. Roblox paid-random-item and Premium rules reviewed (§38.1).

## Systems and modules

No new systems. Work is spread across existing modules:
- bug fixes;
- tuning moved into shared config modules;
- performance fixes;
- content completion against catalogs (items, recipes, events, bosses, quests, perks).

## Data and persistence

- Final `schemaVersion` with migrations tested from every earlier version used in playtests.
- Decide whether to reset the playtest profile DataStore at launch. If yes, use a new DataStore name rather than deleting data.

## Security and anti-exploit

- Re-run the full v0.17 security suite.
- Review admin allowlists, remove test commands, rotate API keys if needed and confirm repository secrets.

## UX and accessibility

- Final pass over every screen on desktop, touch and controller.
- Store page: icon, thumbnails, description and age/content questionnaire.

## Validation

**Automated:** the complete CI suite on `main` (specs, publish safety, Rojo build) plus the full security suite.

**Release checklist:**
1. Every GDD regression list above passes on the published place.
2. Manual playtests from GDD §27.2 completed and signed off.
3. 30-player soak test of two or more hours with no data loss and stable memory.
4. Mobile, desktop and console smoke tests.
5. Crash-recovery drill and rollback drill (restore a previous place version from the Creator Dashboard).
6. Economy telemetry checked against the §26.2 healthy signals.
7. GDD §13.2 documentation checklist fully ticked.

## Exit criteria

- [ ] All release checklist items pass.
- [ ] `v0.18` merged to `main`, deployed and verified.
- [ ] `v1.00` version branch created from that `main` commit, and the GDD change log updated for launch.

## Starting placeholders

None. Launch values are whatever playtests have settled by this phase. Every remaining placeholder must either be confirmed by the owner or recorded in the GDD as a deliberate starting value.

## Scope boundary

Post-launch content (new biomes, weapon families, magic, seasonal events, cosmetics stores) belongs to later major versions and needs GDD updates first.
