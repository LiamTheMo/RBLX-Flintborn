# v0.06 — Combat, armor and PvP rules

> **Depends on:** v0.05 · **GDD sources:** §5.1, §5.5, §21.1, §21.5, §35.1 Q26–29, Q33, §37.1 Q66–67, §39.3 Q132–134, Q160b

## Objective

Make primitive PvPvE combat work and stay readable: click melee with per-weapon cadence, slow visible bow arrows that use crafted ammunition, and armor that scales effective HP. Combat is enabled everywhere except designated safe POIs, with no friendly fire, and the server validates every hit.

## Player-facing result

- Click or tap to swing the equipped melee weapon. Rocks hit fast and weakly; spears hit slowly and hard with longer reach.
- Hold to draw a bow. Longer draws send the arrow **farther, never harder**. Arrows fly slowly on a slight arc and are used up from the inventory.
- Equipping Hide, Wood, Stone or Iron armor visibly raises effective health.
- Tribe members cannot hurt each other. Everyone else can be attacked anywhere except inside a marked safe zone.

## Confirmed rules

| Rule | Value | Source |
| --- | --- | --- |
| Attack style | **Click melee** and **slow bow projectiles** only; no shields, blocking, dodge-roll or player magic | Q26, Q29, §5.1 |
| Melee damage (starting targets) | Rock **5**, wooden spear **~15**, stone spear **~25** raw | Q66 |
| Attack cooldowns (approximate) | Rock **0.3 s**, Dagger **0.4 s**, Sword **0.7 s**, Spear **0.9 s** | Q133 |
| Bow damage | **Both bow and arrow tier** set damage; draw time changes **range only** | Q134 |
| Arrows | Crafted, **10 per recipe**, consumed per shot | Q28, Q107 |
| Stamina | Melee and bows **never** use stamina | Q27 |
| Armor | **Effective HP**: `EHP = HP × A`, damage hits EHP, then `HP = EHP / A` | Q67, §21.5 |
| Armor set factors | Full sets: Hide **×1.2**, Wood **×1.5**, Stone **×1.8**, Iron **×2.0** | Q132 |
| Piece stacking | `A = 1 + a_head + a_chest + a_legs`; pieces **add**, never multiply | Q132 |
| PvP | Enabled **everywhere** in the active world except designated safe-zone POIs | Q33 |
| Friendly fire | **None** between tribe members | Q160b |
| Spawn protection | **None**; spawns are spaced from players (v0.03) | Q160b |
| Who can be damaged | Only `ActiveRun` and `ExtractionHolding` characters; never menu, loading, protected-extraction or maintenance states | §31.2 |

`GameConstants.ArmorFactor` and `GameConstants.ApplyDamage` already implement the armor maths and are covered by specs.

## Systems and modules

| Path | Responsibility |
| --- | --- |
| `src/server/Services/CombatService.luau` | Receives attack intent; validates weapon, cooldown, range, arc and target state; applies armor-scaled damage; emits hit events |
| `src/server/Services/ProjectileService.luau` | Server-simulated arrows (position, velocity, gravity) with hit detection, client visual replication and arrow consumption |
| `src/server/Services/SafeZoneService.luau` | Authored safe-zone volumes; rejects damage where attacker or target is protected under the chosen rule |
| `src/shared/Combat/WeaponCatalog.luau` | Damage, cooldown, reach, arc and projectile profile per weapon archetype (data, not code) |
| `src/shared/Combat/ArmorRules.luau` | Per-piece increments for each tier; the full-set sum must equal the confirmed factor |
| `src/shared/Combat/DamageRules.luau` | Pure functions: cooldown check, quality-roll scaling, friendly-fire rule, bow range from draw time |
| `src/client/Controllers/CombatController.luau` | Input (click/tap/trigger), swing animation, local hit feedback, bow draw UI and aim |
| `src/client/Controllers/ProjectileVisualsController.luau` | Smooth arrow visuals following server state |

**Hit validation:** the client may show a predicted swing, but the server decides. It checks the cooldown from the weapon catalog, distance from the attacker's server position (with a latency allowance), the attack arc, line of sight, target state and friendly fire. Any of these failing means no damage.

**Quality rolls:** a weapon's ±5% roll scales its damage; an armor piece's roll scales its increment. How the roll applies to EHP is still Open (§21.5), so use the placeholder and keep it in one function.

## Data and persistence

None persistent. Combat changes run state only: HP, arrows consumed, hit logs for telemetry.

## Security and anti-exploit

From GDD §5.5 and §24:

- forged bow shots, changed projectile speed or hit position, impossible melee reach or rate, and duplicated arrows are rejected;
- damage to a non-active character is rejected (§31.7);
- safe-zone boundaries are checked on the server, including where an arrow started and where it lands;
- replayed attack remotes are dropped by per-player sequence numbers.

## UX and accessibility

- Hit markers and damage numbers use shape and sound, not colour alone.
- The bow draw shows range growth, not damage growth.
- Controller and touch get aim assistance only as allowed for fairness (GDD leaves aim support Open; start with none).
- Safe zones are clearly marked in the world and on the HUD (§3.2).

## Validation

**Automated specs:**
- full sets give 120/150/180/200 EHP;
- mixed pieces add correctly;
- damage never takes HP below 0;
- tribe members cannot damage each other;
- non-active targets take no damage;
- bow damage is the same at every draw time while range grows;
- each weapon's cooldown is enforced.

**Studio checks:**
- Two-player duels with each weapon family.
- Arrows visibly slow and arcing.
- Armor tiers noticeably extend fights.
- Attempt attacks on a menu or loading player: none land.
- Multi-client latency test on a throttled connection.

## Exit criteria

- [ ] Melee and bows work with the confirmed cadence and damage targets.
- [ ] Armor maths matches §21.5 exactly; specs green.
- [ ] No friendly fire, no spawn protection, safe-zone support in place.
- [ ] All §5.5 integrity checks implemented server-side.
