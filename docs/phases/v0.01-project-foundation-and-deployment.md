# v0.01 — Project foundation and deployment pipeline

> **Depends on:** nothing · **GDD sources:** §12 Technical direction, §23.4 Module boundaries, §27.1 #19–20, §28 step 1, design revisions 0.1–1.5

## Objective

Turn the design-only repository into a Roblox project that every later phase can build on: an approved GDD, a Rojo layout, a module loader, a shared rules module, automated validation on every branch and code-only publishing to the live place **only from `main`**.

## Player-facing result

Nothing playable yet. A player joining the published place sees an empty Roblox world. What changes is for the team:

- The GDD (revision 1.5) has every implementation blocker answered by the owner.
- Every push and pull request to `main` or a version branch runs the full validation job.
- Every push to `main` that passes validation updates the live place's scripts automatically.

## Confirmed rules

- **Publishing only from `main`** (GDD §12.2 invariant 9, §27.1 #19). Version branches and minor branches validate but never publish.
- **Server authority** (§12.1): the client handles input, presentation and prediction only. The server decides admission, combat, inventory, crafting, extraction and every persistent write.
- **No firearms, player shields, player magic or equipment durability at launch** (§4, §35). No module may introduce them.
- **The GDD is the source of truth** for gameplay intent. Engineering must not silently change its rules.

## Systems and modules

| Path | Purpose |
| --- | --- |
| `default.project.json` | Rojo tree: `ReplicatedStorage.Shared` ← `src/shared`, `ReplicatedStorage.Assets` ← `src/assets`, `ServerStorage.Maps` ← `src/maps`, `ServerScriptService.Server` ← `src/server`, `StarterPlayer.StarterPlayerScripts.Client` ← `src/client` |
| `src/server/init.server.luau` | Server entry point. Loads every module in `Server/Services` with `Loader` and runs `Init` then `Start` |
| `src/client/init.client.luau` | Client entry point. Loads every module in `Client/Controllers` the same way |
| `src/shared/Core/Loader.luau` | Loads sibling ModuleScripts in name order and runs each lifecycle step in its own `pcall` |
| `src/shared/Core/Signal.luau` | In-process signal for decoupling modules on one side of the network boundary |
| `src/shared/GameConstants.luau` | Owner-confirmed numbers and pure formulas (armor EHP, revive HP, food interruption, stack overflow, best-roll chance, vault slots) |
| `scripts/roblox_cloud_sync.py` | Maps Rojo script files to place instances; `--check` offline, `--dry-run` read-only cloud preflight |
| `scripts/roblox_live_publish.py` | Publishes scripts into the existing place through Luau Execution, saves the place, then verifies sources |
| `.github/workflows/deploy.yml` | `validate` job on PRs and pushes to `main`/`vX.XX`; `deploy` job only on pushes to `main` |
| `tests/luau/` | Headless Luau spec runner (`run.py`, `prelude.luau`) and `*.spec.luau` files for pure shared modules |
| `tests/test_cloud_live_publish.py` | Offline publish-safety tests (allowed roots, no deletes, verification, size limit, preflight under `luau`) |

**Conventions for every later phase:**

- One responsibility per Service (`src/server/Services/<Name>Service.luau`) and Controller (`src/client/Controllers/<Name>Controller.luau`). Adding one is just adding a file.
- Pure rules and catalogs live in `src/shared` so the server, client and headless specs share one definition.
- Tunable values live in shared config modules, never scattered literals.
- Format with StyLua (`stylua src tests/luau`). Selene uses the `roblox` standard library.

## Security and anti-exploit

- The deploy job reads `ROBLOX_API_KEY`, `ROBLOX_UNIVERSE_ID` and `ROBLOX_PLACE_ID` from repository secrets only. Checkouts use `persist-credentials: false`.
- The publisher refuses targets outside `Server`, `Shared` and `Client`, never deletes instances, never uploads a whole place, and checks the entire mapping before its first write.
- If the place's managed roots are missing, the publisher stops instead of creating them. The place must be prepared once with Rojo (below).

## Validation

**Automated (CI `validate` job, also runnable locally):**

```sh
python3 scripts/roblox_cloud_sync.py --check
python3 scripts/roblox_live_publish.py --check
stylua --check src tests/luau
python3 tests/luau/run.py
python3 -m unittest discover -s tests -p 'test_cloud_live_publish.py' -v
rojo build default.project.json --output build/validation.rbxlx
```

`tests/luau/gameconstants.spec.luau` checks the confirmed numbers:
- full-set EHP of 120/150/180/200;
- additive armor pieces;
- revive at 10% of max EHP;
- food heals halving with the ≤10 HP cutoff;
- slowdown strictly below 25% food;
- 1,000-unit stack overflow deletion;
- 1% → 1.05% → 1.5% best-roll chance;
- inventory and vault sizes.

**One-time manual setup of the live place** (see [`docs/roblox-live-deployment.md`](../roblox-live-deployment.md)):

1. In Studio, back up the place, connect Rojo (`rojo serve`) and sync once so `ServerScriptService/Server`, `ReplicatedStorage/Shared` and `StarterPlayer/StarterPlayerScripts/Client` exist. Publish from Studio.
2. In the Creator Dashboard, enable **Allow place to be updated using Save Place API** on the place.
3. Confirm the API key has **Luau execution session task write** for this experience.
4. Close Team Create sessions before a `main` release.

## Scope boundary

- **One place deployed for now.** The owner confirmed **two places** (lobby and play world, Q163). The pipeline currently publishes to the one place named by `ROBLOX_PLACE_ID`. v0.03 must extend the deploy job to publish to both places before relying on the second, using the owner's secret names: **`ROBLOX_LOBBY_PLACE_ID`** for the lobby and **`ROBLOX_MAIN_PLACE_ID`** for the play map. `ROBLOX_PLACE_ID` is retired at that point.
- **No Wally packages.** The code-only publisher does not ship `ReplicatedStorage/Packages`. Before live code depends on a package (for example React for UI), extend the release to ship packages, as RBLX-Tank-Blast does.
