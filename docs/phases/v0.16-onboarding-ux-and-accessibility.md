# v0.16 — Onboarding, UX and accessibility

> **Depends on:** v0.14 · **GDD sources:** §1.2, §11, §20.1, §25 (all), §25.5, §36.5, Q59, §27.1 #17, #37

## Objective

Make Flintborn understandable to a first-time Roblox player on any device:
- a guided tutorial and quests that teach the risk loop;
- a consistent UI pass over every screen built in earlier phases;
- accessibility that never relies on colour alone or precise pointer control.

## Player-facing result

- A **first-session tutorial** and **guided quests** that go from the safe world menu through gathering, crafting, healing, combat basics, events and extraction to the vault. It never hands out free Permanent gear.
- A consistent visual style across the HUD, lobby, vault, Forge, shops, trading, tribe, building and death screens.
- Settings for camera, controls, UI scale and accessibility (reduced motion, colour-blind-safe palette, subtitles for alert sounds).

## Confirmed rules

- **A tutorial and guided quests are required** for the first impression (Q59). It must work with **random spawning** and the **protected world menu**, and never quietly put a loading avatar in danger (§36.5).
- **No free Permanent gear** from the tutorial (§25.5).
- **Keep the full loop understandable**, including on touch and controller (§1.2).
- **Major cues are redundant**: colour, icon, words and sound (§11).
- **No precise-cursor interactions** are required (§11, §25.4).

**Proposed learning order (§25.5, §36.5):**
1. Safe pre-spawn Play and random spawn.
2. Health, food and sprint stamina; camera.
3. Gathering and craftable arrows.
4. Instant medicine and food heal-over-time.
5. Tribes, revives and raid risk.
6. Public weighted events.
7. The shared 120-second extraction, with Center 2×.
8. The always-saved vault.
9. Coins, Gems, rarity, special recipes, masteries and rebirth.

## Systems and modules

| Path | Responsibility |
| --- | --- |
| `src/server/Services/TutorialService.luau` | Tutorial step state per player, step completion from real gameplay events, once-only rewards |
| `src/shared/Tutorial/TutorialSteps.luau` | Ordered steps, triggers, hint text, completion conditions |
| `src/client/Controllers/TutorialController.luau` | Step hints, arrows/markers, skip and replay |
| `src/client/Controllers/SettingsController.luau` | Settings menu with saved preferences |
| `src/client/Ui/` | Shared UI components and theme (spacing, typography, rarity colours with labels, icons) used by every controller |

## Security and anti-exploit

- Tutorial rewards are granted once and only for server-observed completion.
- Skipping never grants rewards.
- Tutorial steps cannot bypass any risk rule. Whether new players get PvP protection is still Open; default none.

## UX and accessibility

- **Interface inventory review** against GDD §25: lobby navigation (Deploy, Secure Vault, Permanent items, Forge, Recipe Tracker, Recent Extractions), post-extraction receipt, Forge browser and conversion, in-world HUD, inventory/merchant/workbench/trading, death screen.
- Text sizes and touch targets follow Roblox mobile guidance. Every action is focusable with a controller.
- Alert sounds (extraction, Horn of War, events) have on-screen subtitles.

## Validation

**Automated specs:**
- tutorial steps are ordered and each has a completion trigger;
- rewards are granted once;
- no step grants a Permanent item.

**Playtests (GDD §27.2):**
- Fresh solo onboarding from spawn through first extraction and first special recipe.
- Testers can explain **Vaulted vs Permanent**.
- Complete the tutorial on desktop, touch and controller without help.
- Colour-blind simulation pass on every screen.

## Exit criteria

- [ ] Tutorial and guided quests teach the full loop on all three input types.
- [ ] Every screen uses the shared UI system and passes the accessibility checklist.
- [ ] Settings persist per profile.
